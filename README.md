# Mini Employee & Task Management System

A full stack role based task management demo for the FIFOTech Programmer selection project. The API is stateless, protects every business endpoint with Spring Security, applies role checks with `@PreAuthorize`, and scopes records by user/team on the backend.

## Tech stack

- Backend: Java 17, Spring Boot 3, Spring Security, JWT, Spring Data JPA, Hibernate, Maven
- Database: MySQL 8
- Frontend: Angular 13, TypeScript, Bootstrap 5
- Reports: PDF task report generated by the API
- Deployment targets: Netlify (frontend), Render or Railway (backend), managed MySQL

## Local setup

Requirements: JDK 17, Maven 3.9+, Node.js 16 (Angular 13 compatible), npm, and MySQL 8.

1. Create a MySQL database and user, then run `schema.sql`.
2. Set the backend variables below, or use local defaults for `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD`.
3. Start the API: `cd backend && mvn spring-boot:run` (default port 8080).
4. Start Angular: `cd frontend && npm install && npm start` (default port 4200).
5. Sign in with one of the demo accounts listed below. The backend initializer creates sample users and tasks with BCrypt encoded passwords when `SEED_DEMO_DATA=true` (default). Set it to `false` for an environment where demo credentials must not be created.

Angular API URL: set `environment.apiUrl` in `frontend/src/environments/environment.ts`; production builds use `environment.prod.ts`.

## Environment variables

| Variable | Purpose | Local default |
|---|---|---|
| `PORT` | HTTP port | `8080` |
| `DB_URL` | JDBC URL | `jdbc:mysql://localhost:3306/taskdb?...` |
| `DB_USERNAME` | MySQL username | `root` |
| `DB_PASSWORD` | MySQL password | empty |
| `DDL_AUTO` | Hibernate schema mode | `update` (use `validate` in production) |
| `JWT_SECRET` | Base64 encoded key, at least 32 decoded bytes | development-only key in `application.yml` |
| `JWT_EXPIRATION_MS` | Token lifetime in milliseconds | `86400000` |
| `CORS_ALLOWED_ORIGINS` | Comma-separated trusted frontend origins | `http://localhost:4200` |
| `SEED_DEMO_DATA` | Add sample users/tasks on first startup | `true` |

## API reference

All endpoints except login require `Authorization: Bearer <token>`. Admin user management is restricted by both URL policy and `@PreAuthorize`. Manager and employee task data is narrowed by the API service, even if a caller changes query parameters.

| Method | Path | Access | Notes |
|---|---|---|---|
| `POST` | `/api/auth/login` | Public | `{ "email", "password" }` -> token, role, name, email, id |
| `POST` | `/api/auth/register` | Admin | Create a user |
| `GET` | `/api/users?page=0&size=10&search=` | Admin | Paginated user search |
| `GET` | `/api/users/{id}` | Admin | User details |
| `POST` | `/api/users` | Admin | Create user |
| `PUT` | `/api/users/{id}` | Admin | Edit user/role/team/active state |
| `DELETE` | `/api/users/{id}` | Admin | Soft-deactivate user |
| `GET` | `/api/users/team` | Manager, Admin | Active employees in the manager's team (admin sees all active employees) |
| `POST` | `/api/tasks` | Manager, Admin | Assign to an active employee; managers can only assign to own team |
| `GET` | `/api/tasks?status=&priority=&assigneeId=` | Authenticated | Role-scoped tasks with filters |
| `GET` | `/api/tasks/{id}` | Authenticated | Own task, own team task, or admin |
| `PUT` | `/api/tasks/{id}/status` | Employee | `{ "status": "IN_PROGRESS" }`, own task only |
| `PUT` | `/api/tasks/{id}` | Manager, Admin | Update task fields |
| `DELETE` | `/api/tasks/{id}` | Admin | Delete task |
| `GET` | `/api/dashboard/stats` | Authenticated | Role-based counts |
| `GET` | `/api/reports/tasks/pdf` | Manager, Admin | PDF; manager sees only own team's tasks |

Task statuses: `PENDING`, `IN_PROGRESS`, `DONE`. Priorities: `LOW`, `MEDIUM`, `HIGH`.

## Deployment notes

Configure `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, a unique random Base64 `JWT_SECRET`, `CORS_ALLOWED_ORIGINS`, `DDL_AUTO=validate`, and `SEED_DEMO_DATA=false` in the backend host. Build Angular with `npm run build`; publish `frontend/dist/frontend` from Netlify and set the production API URL before building. Add an SPA fallback redirect to `/index.html`. Deploy backend using `mvn -DskipTests package` and run `java -jar target/mini-employee-task-management-1.0.0.jar`. Never publish production secrets or commit `.env` files.

## Security and implementation notes

- DTOs keep persistence entities out of the API contract.
- BCrypt is used for seeded and newly created passwords.
- JWT authentication is stateless; disabled accounts cannot authenticate.
- `@PreAuthorize` enforces role boundaries, while service checks protect task ownership and team membership.
- User deletion deactivates the account to preserve task/user foreign-key history.
- Employee status changes may only move forward; completed tasks cannot be reopened.
- Production deployment requires setting a strong secret and a managed MySQL service.
